API Documentation

1. API Information

API Name: Mind Off Run Club API

Base URL: https://mind-off-run-club-api-production.up.railway.app

Backend: Node.js and Express.js

Database: Supabase PostgreSQL

Authentication: Supabase Auth using access tokens

Image Storage: Supabase Storage

General Rules

  • API request and response data generally use JSON.
  • Image uploads use multipart/form-data.
  • Protected endpoints require a valid access token.
  • Successful creation requests generally return HTTP 201.
  • Error responses contain an error message in JSON format.

2. Authentication

The API uses Supabase Authentication. After a successful login, the server returns an access token.

Authorization Header

Authorization: Bearer YOUR_ACCESS_TOKEN

Protected Endpoints

  • GET /profile
  • PUT /profile
  • GET /users
  • GET /friends
  • POST /friends
  • PUT /friends/:id
  • GET /posts
  • POST /posts

The token identifies the logged-in user. The API verifies it through Supabase Auth before processing protected requests.

Authentication Error Example

{
  "error": "Authentication token is required"
}

Status: 401 Unauthorized

4. Sign Up

Endpoint: POST /signup

Authentication: Not required

Purpose: Register a new user account.

Request

Content-Type: application/json

{
  "username": "runner123",
  "email": "runner@example.com",
  "password": "your_password"
}

Expected Result

Creates a Supabase Auth account and a corresponding user profile. Depending on the Supabase email confirmation settings, the user may need to confirm their email before logging in.

Example Response — Account Created

{
  "message": "Account created successfully",
  "user": {
    "id": "user-uuid",
    "username": "runner123",
    "email": "runner@example.com",
    "bio": "",
    "avatar_url": null,
    "created_at": "2026-10-14T00:00:00.000Z"
  },
  "access_token": "supabase-access-token",
  "needsEmailConfirmation": false
}

Example Response — Email Confirmation Required

{
  "message": "Account created. Please confirm your email before logging in.",
  "user": {
    "id": "user-uuid",
    "username": "runner123",
    "email": "runner@example.com",
    "bio": "",
    "avatar_url": null,
    "created_at": "2026-10-14T00:00:00.000Z"
  },
  "access_token": null,
  "needsEmailConfirmation": true
}

Error Examples

Missing required fields:

{
  "error": "Username, email and password are required"
}

Username already exists:

{
  "error": "Username already exists"
}

Status Codes:

  • 201 Created — Account and profile created.
  • 400 Bad Request — Missing fields or Supabase signup error.
  • 409 Conflict — Username already exists.
  • 500 Internal Server Error — Account creation failed.

Direction: Frontend → API → Supabase Auth and PostgreSQL.

5. Login

Endpoint: POST /login

Authentication: Not required

Purpose: Authenticate a user and return an access token.

Request

Content-Type: application/json

{
  "email": "runner@example.com",
  "password": "your_password"
}

Expected Result

Verifies the user's credentials and returns the access token and profile information. Use the token in subsequent protected requests.

Example Response

{
  "message": "Login successful",
  "access_token": "supabase-access-token",
  "user": {
    "id": "user-uuid",
    "username": "runner123",
    "email": "runner@example.com",
    "bio": "",
    "avatar_url": null,
    "created_at": "2026-10-14T00:00:00.000Z"
  }
}

Error Examples

Missing fields:

{
  "error": "Email and password are required"
}

Invalid credentials:

{
  "error": "Invalid email or password"
}

Profile not found:

{
  "error": "User profile not found"
}

Status Codes:

  • 200 OK — Login successful.
  • 400 Bad Request — Missing fields.
  • 401 Unauthorized — Invalid credentials.
  • 404 Not Found — Profile not found.
  • 500 Internal Server Error — Login failed.

Direction: Frontend → API → Supabase Auth → Profile database.

7. Update My Profile

Endpoint: PUT /profile

Authentication: Required

Purpose: Update the logged-in user's profile.

Request

Content-Type: application/json

{
  "username": "newrunner",
  "bio": "Running to clear my mind.",
  "avatar_url": "https://example.com/avatar.png"
}

The username is required. If bio is omitted, it is saved as an empty string. If avatar_url is omitted, it is saved as null.

Expected Result

Updates the profile belonging to the authenticated user.

Example Response

{
  "message": "Profile updated successfully",
  "user": {
    "id": "user-uuid",
    "username": "newrunner",
    "email": "runner@example.com",
    "bio": "Running to clear my mind.",
    "avatar_url": "https://example.com/avatar.png",
    "created_at": "2026-10-14T00:00:00.000Z"
  }
}

Error Examples

{
  "error": "Username is required"
}
{
  "error": "Username already exists"
}

Status Codes:

  • 200 OK — Profile updated.
  • 400 Bad Request — Username missing or empty.
  • 401 Unauthorized — Missing or invalid token.
  • 404 Not Found — Profile not found.
  • 409 Conflict — Username already exists.
  • 500 Internal Server Error — Update failed.

Direction: Frontend → API → PostgreSQL.

9. Send a Friend Request

Endpoint: POST /friends

Authentication: Required

Purpose: Send a friend request to another user.

Request

Content-Type: application/json

{
  "friend_id": "another-user-uuid"
}

Expected Result

Creates a friendship record with status pending. The authenticated user becomes the requester, and the selected user becomes the receiver.

Example Response

{
  "message": "Friend request sent",
  "friendship": {
    "id": "friendship-uuid",
    "requester_id": "user-uuid",
    "receiver_id": "another-user-uuid",
    "status": "pending",
    "created_at": "2026-10-14T00:00:00.000Z"
  }
}

Error Examples

Missing friend ID:

{
  "error": "Friend ID is required"
}

Adding yourself:

{
  "error": "You cannot add yourself as a friend"
}

Existing request or friendship:

{
  "error": "A friend request or friendship already exists"
}

Status Codes:

  • 201 Created — Friend request sent.
  • 400 Bad Request — Missing ID or self-request.
  • 401 Unauthorized — Missing or invalid token.
  • 404 Not Found — Target user not found.
  • 409 Conflict — Request or friendship already exists.
  • 500 Internal Server Error — Request creation failed.

Direction: Frontend → API → PostgreSQL.

11. Accept a Friend Request

Endpoint: PUT /friends/:id

Authentication: Required

Purpose: Accept an incoming pending friend request.

Request

PUT /friends/friendship-uuid

Authorization: Bearer YOUR_ACCESS_TOKEN

Replace :id with the friendship record ID, not the requester's user ID. No request body is required.

Expected Result

Updates the friendship status from pending to accepted. Only the receiver of the pending request can accept it.

Example Response

{
  "message": "Friend request accepted",
  "friendship": {
    "id": "friendship-uuid",
    "requester_id": "another-user-uuid",
    "receiver_id": "user-uuid",
    "status": "accepted",
    "created_at": "2026-10-14T00:00:00.000Z"
  }
}

Error Example

{
  "error": "Pending friend request not found"
}

Status Codes:

  • 200 OK — Request accepted.
  • 401 Unauthorized — Missing or invalid token.
  • 404 Not Found — No matching pending request for this receiver.
  • 500 Internal Server Error — Acceptance failed.

Direction: Frontend → API → PostgreSQL.

12. Create a Post

Endpoint: POST /posts

Authentication: Required

Purpose: Create a text post with an optional image.

Request

Content-Type: multipart/form-data

Form fields:

  • title — Optional text.
  • content — Required text.
  • visibility — Required; either public or friends.
  • image — Optional image file; maximum size 5 MB.

Example form data:

title: My Morning Run
content: Enjoyed a peaceful run today!
visibility: public
image: [select an image file]

When sending an image, use multipart/form-data. Do not send the image as a JSON string or manually set the multipart Content-Type header when using browser FormData; the browser must add its boundary.

Expected Result

Uploads the optional image to the Supabase Storage bucket post-images, saves the post and its storage path in PostgreSQL, and returns the created post.

Example Response

{
  "message": "Post created successfully",
  "post": {
    "id": "post-uuid",
    "user_id": "user-uuid",
    "title": "My Morning Run",
    "content": "Enjoyed a peaceful run today!",
    "image_url": "user-uuid/generated-image-name.jpg",
    "visibility": "public",
    "created_at": "2026-10-14T00:00:00.000Z"
  }
}

The returned image_url is the stored image path, not a public image URL. GET /posts generates a temporary signed URL for displaying it.

Error Examples

Missing content:

{
  "error": "Content is required"
}

Invalid visibility:

{
  "error": "Visibility must be public or friends"
}

File larger than 5 MB:

{
  "error": "Image must be 5 MB or smaller"
}

Non-image file:

{
  "error": "Only image files are allowed."
}

Other creation failure:

{
  "error": "Failed to create post"
}

Status Codes:

  • 201 Created — Post created.
  • 400 Bad Request — Invalid fields or upload validation error.
  • 401 Unauthorized — Missing or invalid token.
  • 500 Internal Server Error — Upload or post creation failed.

Direction: Frontend → API → Supabase Storage and PostgreSQL.

13. Get Feed Posts

Endpoint: GET /posts

Authentication: Required

Purpose: Retrieve posts that the logged-in user is allowed to see.

Request

GET /posts

Authorization: Bearer YOUR_ACCESS_TOKEN

Expected Result

The API returns:

  • All public posts.
  • The logged-in user's own posts, including friends-only posts.
  • Friends-only posts from users with an accepted friendship.

Posts are ordered newest first. Each post includes author information. If an image exists, image_url is replaced with a temporary signed URL that expires after one hour.

Example Response

[
  {
    "id": "post-uuid",
    "user_id": "another-user-uuid",
    "title": "Evening Run",
    "content": "A great run with the community!",
    "image_url": "https://example.supabase.co/storage/v1/object/sign/...",
    "visibility": "public",
    "created_at": "2026-10-14T00:00:00.000Z",
    "username": "runner456",
    "avatar_url": null
  },
  {
    "id": "another-post-uuid",
    "user_id": "user-uuid",
    "title": "Personal Progress",
    "content": "Happy with today's progress.",
    "image_url": null,
    "visibility": "friends",
    "created_at": "2026-10-13T00:00:00.000Z",
    "username": "runner123",
    "avatar_url": null
  }
]

Error Example

{
  "error": "Failed to get posts"
}

Status Codes:

  • 200 OK — Posts retrieved, including an empty array if none are visible.
  • 401 Unauthorized — Missing or invalid token.
  • 500 Internal Server Error — Failed to get posts.

Direction: Frontend → API → PostgreSQL → Supabase Storage for signed image URLs.

14. Common HTTP Status Codes

  • 200 OK: The request succeeded.
  • 201 Created: A resource was created.
  • 400 Bad Request: Required fields or input values are invalid.
  • 401 Unauthorized: Authentication is missing or invalid.
  • 404 Not Found: The requested resource or route was not found.
  • 409 Conflict: The request conflicts with an existing username, request, or friendship.
  • 500 Internal Server Error: The server could not complete the request.

15. General Error Handling

Unknown Route

Example: GET /unknown-route

{
  "error": "Route not found"
}

Status: 404 Not Found

Unexpected Server Error

{
  "error": "Internal server error"
}

Status: 500 Internal Server Error

Authentication Failure

Protected endpoints return HTTP 401 when the token is missing, malformed, expired, or cannot be verified.
